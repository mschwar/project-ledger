## Summary

Implemented the **P2.3 identity evidence model** (`ledger/evidence.py`, SCHEMA.md §1.8):
records and *scores* the identity evidence observations and canonical projects carry, so
agents can see *why* observations unified (or did not) without re-running archaeology.
Scoring is descriptive — it does **not** widen the merge authority, which remains
exactly one rule (exact normalized repository remote) plus explicit durable decisions.

## What landed

- `ledger/evidence.py` — new module:
  - evidence kind taxonomy (`evidence_kinds()`) with strength class
    `strong` / `weak` / `negative`;
  - deterministic evidence records (`identity_evidence_id = stable_id("ev", kind,
    members, value)`) for every kind: normalized remote, source-native identity,
    explicit merge decision, explicit project key/declaration, path locator +
    path migration alias, raw URL, display name, README/repo compound, name/semantic
    similarity, negative decision, conflicting decision;
  - `observation_evidence()` — per-observation extraction across all spec'd types;
  - `score_pair()` — pair verdict: `strong_match` / `weak` / `none` (descriptive);
  - `project_identity_evidence()` — per-canonical-project unifying evidence + `summary`
    (unifying authority, strong reason code, automatic flag, weak-overlap pair count);
  - `build_identity_evidence()` — materializes `state/identity-evidence.json`
    (`by_project` keyed by observation membership + `cross_project_weak_overlaps`).
- `ledger/identity.py` — `observation_facts` made public and extended (source_id,
  snapshot_id, readme facts) and reused by the evidence model; per-canonical-project
  `identity_evidence[]` now comes from the model and adds `identity_evidence_summary`;
  `materialize_identity` writes `identity-evidence.json`. Imports are lazy to avoid a
  module-load cycle (evidence.py imports identity's observation_facts).
- `ledger/compiler.py` — registers `identity_evidence` as an available capability and
  artifact, and `counts.identity_evidence`.
- `ledger/__init__.py` — `IDENTITY_EVIDENCE_SCHEMA_VERSION = "1.0.0"`.
- `tests/test_identity_evidence.py` — 13 tests covering taxonomy, observation records,

## Evidence classification (the P2.3 scoring axis)

| Strength | Kinds |
| --- | --- |
| strong | `normalized_remote`, `source_native_identity`, `explicit_merge_decision` |
| weak (referents only — never auto-merge) | `explicit_project_key`, `raw_url`, `path_locator`, `path_migration`, `display_name`, `readme_compound`, `name_similarity`, `semantic_similarity`, `cross_project_weak_overlap` |
| negative | `negative_decision`, `conflicting_decision` |

Weak name/semantic similarity is explicitly marked weak (`referent_only`); pairs that
share only weak referents score `weak` and never merge — proven by
`test_weak_similarity_does_not_merge_two_projects` and
`test_name_only_overlap_is_weak_and_never_strong`. Negative split/reject evidence is
recorded as first-class negative evidence
(`test_negative_decision_is_recorded_as_negative_evidence`).

## Latent finding surfaced (owned by P2.5)

Two *distinct* canonical projects can briefly share a `canonical_project_id` when a
split/reject keeps two observations that still share an exact remote (the identity
anchor still prefers the shared remote for each component, e.g. both split singletons
anchor to `prj_3988fba6…` for the same `reject_match` pair). Confirmed **pre-existing**
on `main` (not introduced by P2.3). The evidence store keys `by_project` by observation
membership so it stays lossless/deterministic; the colliding anchor is corrected in
P2.5 canonical-ID work. Documented in SCHEMA.md §1.8, CURRENT.md and this handoff.
