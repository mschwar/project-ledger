## The defect (colliding canonical ID)

When a `split`/`reject_match` decision kept two observations that share an exact
normalized remote in separate conceptual projects, the compiler derived the anchor for
*both* components from the shared remote:

```text
canonical_project_id = stable_id("prj", "normalized_remote", <shared remote>)
```

Both projects therefore received the **same** `canonical_project_id`, violating
SCHEMA.md invariant #1 (canonical IDs immutable and unique per conceptual project) and
breaking `ledger resolve` (two projects under one ID). The evidence store keyed
`by_project` by observation membership so it stayed lossless, but the canonical ID
itself collided.

## What landed

- `ledger/identity.py`:
  - A normalized remote is now only used as the identity anchor when it is **unique to
    one project** across the whole compile. The compiler builds a
    `remote -> {project memberships}` map; a remote that maps to more than one project
    (i.e. a split/reject kept observations sharing it apart) can no longer anchor any of
    them. Each such project falls back to a membership-scoped anchor (`observation` or
    `merge_decision`), so every project gets a distinct, stable `canonical_project_id`.
  - Added a `resolved_fields` claim-provenance map to each canonical project. For the
    resolved `project_key` and `display_name`, it records which
    observation/decision/evidence produced the value: `decision` (canonical_key),
    `declaration` (project_key sidecar), `observed` (remote/name), or `derived`
    (fallback). A cold agent can now see *why* a canonical value exists without
    re-running archaeology.
- `tests/test_p25_canonical_ids.py` — 8 tests covering: split and reject_match keeping
  same-remote observations in distinct projects (no ID collision), the unique-remote
  case still anchoring `normalized_remote` (common case not degraded), split-ID
  stability across repeated compiles, and `resolved_fields` provenance for
  declaration / canonical_key / observed-remote / display-name sources.
