## Summary

Completed the **P2.4 decision registry**: the durable identity-decision input contract
now covers the full decision-type set and carries enriched provenance. The walking
skeleton already supported `merge`, `split`, `reject_match`, and `alias`; this work adds
**canonical human key assignment** (`canonical_key`) and **supersession** (`supersede`),
and validates the enriched decision fields (`rationale`, `evidence`, `authority`,
`decided_at`). Supersession is append/supersede oriented — a superseded decision is
inactive for the compile, never silently rewritten.

## What landed

- `ledger/identity.py`:
  - `_DECISION_TYPES` extended with `canonical_key` and `supersede`;
  - `_DECISION_AUTHORITIES` = `operator` | `trusted_automation` | `reviewed_agent`;
  - `load_identity_decisions` validates the new types and the enriched fields

    `key`; `supersede` requires `supersedes_decision_id` and cannot self-supersede);

    `canonical_key_decision_id` on the canonical project.

  - `_active_decisions()` filters out superseded decisions so superseded negative

    `negative_decision_ids_by_pair`).
- `tests/test_decision_registry.py` — 10 tests covering validation, canonical-key
  override + membership stability, supersession unblocking an auto-merge, superseded

## Decision types (final P2.4 set)

| Type | Effect |
| --- | --- |
| `merge` | explicitly union two or more observation IDs |
| `split` | keep listed observation IDs in separate conceptual projects |
| `reject_match` | reject one specific observation pair |
| `alias` | attach an operator-approved exact referent to a project |
| `canonical_key` | assign an operator-approved stable `project_key` (overrides auto-derived; never changes membership) |
| `supersede` | mark a prior decision inactive for the compile (append/supersede oriented) |

Every decision carries a stable `decision_id` and may carry `rationale`, `evidence`
refs, `authority`, and `decided_at`.
