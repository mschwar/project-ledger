# P1.5 — Tighten freshness/result semantics (2026-09-20)

## What

Closed the Gate B contract item **P1.5: tighten freshness/result semantics**. The
materialized source records in the system manifest now distinguish three real scan
outcomes, expose an authoritative upstream `as_of` where one genuinely exists, and
never invent freshness.

## Deliverables

1. **Unavailable vs successfully-observed-empty vs observed** — each source in
   `manifest.sources[]` now carries:
   - `result_state`: `observed` | `observed_empty` | `unavailable`;
   - `observation_count`: the number of typed observations resolved to this source in
     this compile.
   A source that is probed successfully but yields zero observations is
   **`observed_empty`** (healthy, not broken) — a deliberately distinct state from
   `unavailable` (root/inventory artifacts inaccessible). The manifest `health` block
   gains `observed_empty_source_count` so agents can see empty-but-healthy sources
   without treating them as failures.
2. **Stronger `as_of` semantics where upstream supplies evidence** — the source
   freshness is `known` only when genuine authoritative timestamp evidence is present,
   exposed as `content_as_of` + `content_as_of_basis`. Authoritative priority:
   git remote-ref committer date (`compat.entry.last_remote_ref_at`) > HEAD commit date
   (`compat.entry.head_commit_at`) > filesystem last-touch (`compat.entry.last_touch_at`).
3. **No invented freshness** — an observed source with no authoritative timestamp stays
   `freshness_state: unknown` with `content_as_of: null`; a probeable-but-unreachable
   source is `unavailable`. Freshness is never derived from compile time or path mtime
   (`probe_as_of` remains current-probe evidence, explicitly not content freshness).

## Why

P1.5 is the last dependency-ordered Gate B source/freshness item. Agents reading one
manifest needed to distinguish "this source is broken/unreachable" from "this source is
healthy but has nothing" — previously both collapsed into the availability `status`,
and `freshness_state` was a constant `unknown` with no honest path to `known` even when
the upstream git source supplied authoritative commit timestamps.
